# Engine과 Aside 연결 계약

## 접수부터 완료까지

1. 플랫폼 어댑터가 지정 소유자·워크스페이스 또는 서버·채널·스레드를 검증합니다.
2. 새 대화의 `AsideSettings.readPreset` 결과를 스레드와 요청에 저장합니다. 후속 질문은 접수 시점의 스레드 설정을 요청에 저장합니다.
3. Engine은 해당 플랫폼 대기열에서 하나씩 처리하고 Aside health를 확인합니다.
4. 세션이 없으면 `createSession(selection)` 반환 ID를 영속 바인딩에 기록한 뒤 질문을 실행합니다.
5. `runTurn`은 소유권, 새 동일 턴의 완료, 지정 모델의 최종 텍스트를 검증합니다. 생성 최대 300초·완료 대기 최대 60분입니다.
6. Engine은 모델 일치를 다시 검사하고 완료 답변을 전송 대기열에 기록합니다. 실행과 전송 상태를 별도로 관리합니다.

플랫폼 연결은 `Engine.setConnected`로 전달합니다. 끊긴 동안 새 제출과 미시도 전송을 보류하며, 실행 준비 후와 `runTurn`의 마지막 제출 직전에도 연결을 검사합니다. `Store.deferUnsubmitted`는 실제 사용자 질문을 아직 제출하지 않은 경우에만 원문·최초 만료 시각을 보존해 대기 상태로 돌립니다. 제출 후에는 자동 재실행하지 않습니다.

기존 스냅샷 없는 대화는 Luna/medium·속도 미지정 설정을 유지합니다. Slack 스레드의 명시적 프리셋 변경은 실행·대기·불명확 요청이 없는 경우에만 허용하며 `backend_id`와 대화 기록을 유지합니다. 기존 세션의 생성 설정은 `bootstrap_model_selection`으로 보존하여 소유권 검증과 중단에 사용합니다. 변경한 대화는 매 질문 제출 전 `sessions.update`로 모델·추론·속도만 적용하며 권한은 변경하지 않습니다. 속도 미지정 프리셋으로 전환하면 이전 fast 설정이 남지 않도록 false를 지정합니다. 세션 조회 API는 모델을 반환하지 않으므로 변경 성공 응답과 세션 상태를 확인하고, 실제 응답 모델은 완료 기록으로 검증합니다. Effort는 지정값이며 별도 조회 검증은 하지 않습니다. 실패 시 질문은 제출하지 않습니다. 이전 요청의 설정 스냅샷은 변경하지 않으며 프리셋 정의 편집은 기존 대화에 자동 반영하지 않습니다.

새 버전 시작 시 저장소에 생성 설정 보존 열을 추가하고 기존 설정 불변 트리거를 유휴 상태 변경 검증으로 갱신합니다. 기존 바인딩·기록은 유지합니다. 코드 반영에는 봇 재시작이 필요합니다.

## 플랫폼별 답변

`BackendAnswer.text`는 기존 Discord 본문과 출처 목록입니다. 검색 출처가 있으면 목록 첨부 전 `sourceText`와 같은 완료 턴의 `sources`도 제공합니다. 출처는 실제 websearch 결과의 HTTP(S) URL만 사용합니다.

Outbound의 선택적인 `formatAnswer`는 플랫폼별 답변 조각을 만듭니다. Slack은 인용 본문을 유지하며 문단 끝의 완결 문장 뒤에 있는 근거 설명을 별도 문단으로 분리합니다. 실제 매핑되는 출처만 번호와 짧은 링크로 렌더링하며 마지막 메시지의 구분선 아래에 한 줄씩 표시합니다. 답변 본문은 네이티브 Markdown 블록으로 보냅니다. 전송 전에 렌더링 결과를 저장하므로 재시작 후에도 같은 답변을 사용합니다. Discord는 기존 텍스트 분할 경로를 유지합니다.

`progressNotices` 기본값은 기존 10초 진행 안내입니다. Slack만 false로 설정하여 새 안내를 만들지 않고 이전 버전의 미전송 진행 안내도 보내지 않습니다. 최종 답변의 실제 생성 경과 시간은 모두 유지합니다.

## 불명확 상태

재시작으로 끊긴 요청은 `uncertain/interrupted`로 보존하고 해당 플랫폼의 새 실행을 차단합니다. 원 질문을 자동 재실행하지 않습니다. 공식 stop 재확인은 `stop_unconfirmed`·`stop_failed`에만 적용합니다. 중단 수락과 완전 종료는 구분합니다.

생성 명령 또는 사용자 질문 제출 전 CLI 통신 오류는 `BackendFailureError/session_preflight_unavailable`입니다. 생성 명령 시작 뒤에는 기존 불명확 상태 규칙을 유지합니다. 질문 제출 응답 유실이나 제출 후 조회 통신 오류는 동일 세션의 완료 기록 읽기만 재시도하며 기존 60분 한도·턴·소유권·모델 검증을 유지합니다.

Discord의 시간 제한 있는 nonce 재시도와 Slack의 POST 자동 재시도 금지는 Outbound 계약으로 전달합니다. 최종 답변이 확인된 뒤의 안내 삭제 실패는 답변 재전송의 근거가 아닙니다. [운영 안내](../../docs/operations.md)를 참고하세요.
